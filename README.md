# Измерение времени работы сортировок

## Задача

Реализовать пузырьковую сортировку и сортировку вставками. Измерить время их работы на массивах разного размера и посмотреть, как время меняется при увеличении количества элементов.

## Файлы

- `BubbleSort.java` — пузырьковая сортировка, проверки и замер времени.
- `InsertionSort.java` — сортировка вставками, проверки и замер времени.

Каждый файл запускается отдельно. Названия файлов совпадают с названиями публичных классов.

## Как работают алгоритмы

Пузырьковая сортировка сравнивает соседние элементы и меняет их местами, если они стоят в неправильном порядке. После каждого прохода самый большой элемент необработанной части оказывается в конце. Если за проход не было обменов, сортировка заканчивается.

Сортировка вставками постепенно собирает отсортированную часть массива слева. Очередной элемент сохраняется в переменную. Элементы слева, которые больше него, сдвигаются вправо, после чего сохранённый элемент вставляется на свободное место.

## Проведение эксперимента

Используются размеры: 10, 100, 200, 400, 800, 1600, 3200, 6400 и 12800. Начиная со 100, каждый следующий размер в два раза больше предыдущего.

Перед каждым замером создаётся новый массив в обратном порядке:

```java
for (int i = 0; i < n; i++) {
    arr[i] = n - i + 1;
}
```

Например, при n = 5 получается `[6, 5, 4, 3, 2]`. Это худший случай для обеих реализаций.

Время измеряется с помощью `System.nanoTime()`. В измеряемый участок входит только вызов сортировки. Создание массива, проверка результата и вывод выполняются отдельно.

Для каждого размера выполняются три измерения, затем выводится среднее время в наносекундах. Перед экспериментом выполняются пять запусков на массивах из 1000 элементов для небольшого прогрева JVM. Такой прогрев уменьшает часть начальных накладных расходов, но не устраняет все колебания времени.

## Запуск

Нужен установленный JDK версии 8 или новее. Откройте терминал в папке с файлами и выполните:

```text
javac -encoding UTF-8 BubbleSort.java InsertionSort.java
java BubbleSort
java InsertionSort
```

Каждая программа выведет таблицу с двумя столбцами: размер массива и среднее время в наносекундах. Чтобы сохранить результаты в текстовые файлы, можно выполнить:

```text
java BubbleSort > bubble-results.txt
java InsertionSort > insertion-results.txt
```

## Проверка корректности

В обе программы включены проверки следующих массивов:

| Вход | Ожидаемый результат |
| --- | --- |
| `[5, 1, 3, 1, -2]` | `[-2, 1, 1, 3, 5]` |
| `[]` | `[]` |
| `[7]` | `[7]` |
| `[1, 2, 3, 4]` | `[1, 2, 3, 4]` |
| `[4, 3, 2, 1]` | `[1, 2, 3, 4]` |

Ожидаемый результат в коде получается через `Arrays.sort()` на копии массива. Проверяется полное совпадение массивов. В самих реализациях исследуемых сортировок готовая сортировка не используется.

После каждого замера также проверяется, что массив содержит последовательность от 2 до n + 1. При неправильном результате программа завершится с `AssertionError`.

Пузырьковая сортировка корректна, потому что каждый проход ставит максимальный элемент оставшейся части на его окончательное место. Сортировка вставками корректна, потому что после каждой вставки обработанная часть остаётся отсортированной. После обработки всех элементов упорядочен весь массив.

Проверка выполнена 31 октября 2026 года: оба файла скомпилированы компилятором Eclipse ECJ 3.26.0 для Java 8 и запущены на Java HotSpot 64-Bit Server VM 1.8.0_491-b10 под Windows. Обе программы завершились без ошибок: все встроенные проверки пройдены. Исходный код измерений не изменялся.

## Сложность и ожидаемое поведение

| Алгоритм | Лучший случай | Средний случай | Худший случай | Дополнительная память сортировки |
| --- | --- | --- | --- | --- |
| Пузырьковая с проверкой обменов | O(n) | O(n²) | O(n²) | O(1) |
| Вставками | O(n) | O(n²) | O(n²) | O(1) |

На обратном массиве обе реализации выполняют n(n − 1) / 2 сравнений элементов. Пузырьковая сортировка делает столько же обменов, а сортировка вставками — столько же сдвигов. Поэтому при удвоении достаточно большого n ожидается рост времени примерно в четыре раза.

Точное отношение времени может отличаться из-за работы JVM, фоновых процессов и погрешности измерений. Особенно заметны колебания на маленьких массивах. Переход от 10 к 100 не является удвоением, поэтому для него нельзя ожидать роста в четыре раза.

Память O(1) относится к самим методам сортировки: они изменяют переданный массив и используют несколько переменных. Массив для эксперимента и копия для проверки требуют O(n) памяти.

## Вывод

На больших массивах результаты согласуются с квадратичной сложностью обеих сортировок. При переходе от 6400 к 12800 элементам время пузырьковой сортировки выросло с 8 111 200 до 32 286 567 нс — примерно в 3,98 раза. Для сортировки вставками время выросло с 12 100 366 до 48 359 200 нс — примерно в 4,00 раза.

В этом запуске на 12800 элементах пузырьковая сортировка оказалась примерно в 1,50 раза быстрее сортировки вставками. Это результат конкретных реализаций и среды выполнения, а не общее правило для этих алгоритмов.

На небольших размерах видны скачки и даже снижение времени при увеличении массива. Пяти прогревочных запусков недостаточно для полной стабилизации JIT-компиляции; также возможны влияние фоновой нагрузки и погрешность коротких измерений. Значения записаны без сглаживания. Для более точного сравнения потребуются более длительный прогрев и дополнительные повторения.
